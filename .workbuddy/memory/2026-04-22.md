## BUG 修复：音画对齐引擎首次运行失败（6个镜头全部 FAILED_FALLBACK）

### 根因分析（2个独立 bug）

| # | 策略 | 报错 | 根因 |
|---|------|------|------|
| **BUG-A** | PAD_AUDIO_SILENCE (5个镜头) | `Protocol 'https' not on whitelist 'file,crypto,data'!` + `ConcatAudios 失败 (退出码: -22)` | `concatTwoAudios()` 直接把远程 HTTPS URL 写入 concat demuxer 列表文件，但 FFmpeg concat 协议只支持 `file,crypto,data` 白名单 |
| **BUG-B** | DIRECT_BLEND (1个镜头) | `Unable to parse "original_size" option value "\Data\...shot_002..." as image size` + `DirectBlend 失败 (退出码: -22)` | `addSubtitleFilter()` 用 `\\` 转义 Windows 反斜杠传给 FFmpeg，但 `\D` 被 subtitles 滤镜当成转义序列解析导致路径错误 |

### 修复内容

**AudioSyncEngine.java — 2处改动:**
1. **`concatTwoAudios()`**: 新增 `resolveLocalPath()` 辅助方法，检测到 HTTPS URL 时先通过 `videoComposeService.downloadVideoToTemp()` 下载到本地临时文件，再将本地路径写入 concat 列表。用完自动 cleanup
2. **`addSubtitleFilter()`**: 改用正斜杠 `/` 替代反斜杠 `\`（FFmpeg 在 Windows 上完全支持正斜杠），同时改用双引号包裹路径

**VideoComposeService.java — 1处改动:**
3. **`downloadVideoToTemp()`**: 访问修饰符从 `private` 改为包级可见（无关键字），供 AudioSyncEngine 复用

### 第三轮修复：Phase 0 统一预下载（FinalMix 仍全部 -22）

**症状演变**: `ConcatAudios`(第1轮) → `PadSilence-FinalMix`/`DirectBlend`(第2轮) — 说明前两轮修复生效，但 FinalMix 步骤仍有问题

**根因**: `composeWithSync()` 的 Phase 3 所有策略的 FFmpeg 命令中，视频/音频输入仍然是远程 HTTPS URL。FFmpeg 在组合使用 subtitles 滤镜 + 远程输入时支持不稳定（协议白名单、滤镜解析等兼容问题）

**修复**: 在 `composeWithSync()` 入口新增 **Phase 0: 远程文件预下载层**：
- 统一调用 `resolveLocalPath()` 预下载视频+音频到本地临时文件
- Phase 1~4 全部使用本地路径
- `finally` 块确保清理所有临时文件

**铁律**: **AudioSyncEngine 内部所有 FFmpeg 操作只使用本地文件路径** — 这是 FFmpeg + 字幕滤镜稳定工作的前提

### 第四轮修复：subtitles 滤镜盘符冒号被当选项分隔符 (11:41)

**致命日志**: `subtitles="C:/Data/..."` → `[Parsed_subtitles_0] Unable to parse "original_size" option value "/Data/..." as image size`
**根因**: FFmpeg 滤镜解析引擎把 `C:` 的冒号当成 **选项名=值** 分隔符！`C`=选项名, `/Data/...`=值 → original_size 解析失败
**修复**: addSubtitleFilter() Step2 — `replaceAll("^([a-zA-Z]):", "$1\\\\:")` 转义盘符冒号为 `C\:/path`

### BUG00035 四轮修复完整链路

| 轮次 | 时间 | 根因 | 修复点 |
|------|------|------|--------|
| R1 | 11:14 | concat demuxer HTTPS 白名单 | resolveLocalPath for concat |
| R2 | 11:30 | FinalMix 远程URL | Phase 0 统一预下载 |
| R3-R4 | 11:41 | 字幕路径 `\D`(R3) + **`C:`冒号**(R4) | 正斜杠 + **冒号转义** |

4. 用双引号包裹 filter 参数值

### 第五轮修复(R5)：音频文件下载后无校验导致 mp3float Header missing (12:05)

**致命日志**: `[mp3float @ ...] Header missing` + `Invalid data found when processing input`
**症状演变**: R4字幕路径问题 → R5音频数据无效 — 说明R4修复已生效，但新问题暴露

**根因链路**:
```
DB audio.audio_url (OSS临时URL, 可能已过期)
  → resolveLocalPath() 检测到 https://
    → downloadVideoToTemp() RestTemplate.getForEntity()
      → OSS返回: HTML错误页/空响应/重定向目标丢失

          → FFmpeg当MP3解码 → 找不到帧头 → Header missing → 退出码-22
```

**核心缺陷**: 下载后零校验，直接喂给 FFmpeg

**R5 修复（3处改动）**:
1. **AudioSyncEngine Phase 0.5 新增 `isValidAudioFile()` 校验层**
2. **VideoComposeService.downloadVideoToTemp() 增强**: HTTP状态码+空响应+<512B可疑检查
3. **降级策略**: 无效音频 → VIDEO_ONLY（纯画面+字幕），镜头不再 FAILED_FALLBACK

### 第六轮修复(R6)：字幕路径终极方案 — 纯文件名+工作目录 (12:23)

**致命日志（双重问题）**:
```
① [Parsed_subtitles_0] Unable to parse "original_size" option value "/Data/...shot_006.mp4.ass" as image size  ← 注意！没有 C: 盘符！
② [mp3float @ ...] Header missing  ← 音频仍无效
```

**关键发现**: 字幕路径是 `/Data/...` 而非 `C:/Data/...`！说明 R4 的冒号转义方案被 FFmpeg 解析后把盘符"吃掉"了。

**结论**: **Windows 下 FFmpeg subtitles 滤镜传绝对路径始终不可靠**。无论怎么转义都有问题。

**R6 终极修复（字幕部分）**：
- ❌ 删除 `addSubtitleFilter()` 绝对路径方法（治标不治本）
- ✅ 新增 `prepareSubtitleForFFmpeg()`:
  1. 将 ASS 文件复制到输出视频同目录
  2. 返回纯文件名（如 `sub_1713778200000.ass`）——不含任何驱动器号、冒号、反斜杠
- ✅ `executeFf()` 新增 `Path workDir` 参数 → 设置 `ProcessBuilder.directory(workDir)`
- ✅ VideoOnly/DirectBlend/ExtendFreeze/PadSilence 全部改造使用新方案

```java
// ❌ 旧方案(R4): subtitles="C\\:/path/to/file.ass" → 仍有解析问题
// ✅ 新方案(R6): pb.directory(outputDir) + subtitles='sub_xxx.ass'
```

**FFmpeg Windows 字幕铁律（最终版）**:
1. **永远不传绝对路径给 FFmpeg subtitles 滤镜**
2. 改为: 复制ASS到输出目录 → 纯文件名 → ProcessBuilder.directory(cwd)
