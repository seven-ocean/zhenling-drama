## BUG00014: AI配置列表只显示enabled记录

**根因**: `AiConfigService.listByType()` 含 `eq(enabled, true)` 条件，前端4次并行请求 → 禁用配置被过滤 → 列表为空。更严重的副作用：禁用后配置永久消失无法操作。

**修复**:
1. Service: 新增 `listAll()` 方法（仅查 deleted=0，不限 enabled）
2. Controller: 新增 `GET /api/v1/ai-configs` 端点
3. 前端API: aiConfig.ts 新增 `list()` 方法
4. 前端页面: loadConfigs() 从"4次并行 listByType"改为"单次 list()"，移除不再需要的 allApiTypes 常量

## BUG00011 二次修复（上传失败 + 预览空白 + 删除无效）

**根因(3个独立问题)**:
1. `storage.ts` 双重 baseURL 前缀：ofetch 实例自带 `/api/v1`，方法又手动拼 `${baseURL}/storage/...` → 实际请求 `/api/v1/api/v1/storage/...` → 404
2. 缺少本地文件下载端点：FileStorageService 生成本地 URL `/api/v1/assets/download/xxx` 但 AssetController 无此端点 → 图片/视频/音频全部 404
3. 删除也受影响：同样双重前缀导致 404

**修复(2个文件)**:
| 文件 | 变更 |
|------|------|
| frontend/src/utils/storage.ts | 移除所有 `${baseURL}` 拼接，改为相对路径 |
| backend/.../AssetController.java | 新增 `GET /download/**` 端点（路径穿越安全检查 + MIME自动识别 + inline展示） |
